# 岗位与题库列表：表格 / Word 转 CSV 导入说明

本文档说明如何将 **Excel 等表格** 或 **Word 文档** 整理为符合 OpenStar 管理后台 **「岗位」** 与 **「题库」** 批量导入要求的 **`.csv` 文件**。导入规则与后端解析一致：UTF-8（含 BOM 亦可）、首行为表头、列名区分大小写。

---

## ★ 转换前必做（岗位）

### 0. 若由 AI 转换：交表格 / 说明文档前须先完成（岗位）

在把 **原始表格**、**本说明 .md** 或其它材料交给 **AI** 做「表格 → CSV」、列映射或批量生成岗位数据之前，**必须先向管理员落实并在提示词中明文写出**下列两项，**再**提交给 AI；不得在两项未确认时就把表和 md 丢给 AI：

1. **ID 起始询问**  
   - 已按管理后台岗位列表确认：本批 **第一个岗位 `id` = ______**（一般为当前 **最大 `id` + 1**），后续行按 **+1 递增**（或书面约定的其它规则）。  
   - 在给 AI 的说明里写清：「起始 id：______」。

2. **国考还是省考**  
   - 已确认本批岗位 **`category` 全部为「国考」** 或 **全部为「省考」**。  
   - 在给 AI 的说明里写清：「本批 category 一律为：国考 / 省考（二选一）」。

> **未完成以上两项即交给 AI**，易导致 **id 与库内重复或错位**、**国考/省考混填**，导入后难以批量纠正。

### 1. 问清「ID 从多少开始」

**凡是把外部表格转成可导入 CSV，在动手编号之前，必须先向管理员确认本次的起始 ID**，避免与库里已有数据冲突或误覆盖（导入默认多为 **upsert**：相同 `id` 会更新原记录）。

- **原则**：新岗位的 `id` 应取 **管理后台岗位列表里，当前已出现的最大 `id` + 1**，从该数起连续递增。
- **示例**：若后台共有 **55** 条岗位，且其中 **最大的岗位 `id` 恰好为 55**，则新数据从 **`56`** 起编。
- **注意**：若有 **跳号、删除、改过 id**，必须以 **实际最大 `id` + 1** 为准，不能只看总条数。
- **话术**：「请确认：本次批量导入的岗位，第一个 `id` 从 ______ 开始？」

### 2. 问清「本批是国考还是省考」（`category`）

- **每次做表格 → CSV 转换前**，须询问：本次导入的岗位 **`category` 一律填「国考」还是一律填「省考」**。
- **批量添加时**须在任务单或沟通记录里写清：**「本批全部为国考」** 或 **「本批全部为省考」**，整表 `category` 列保持一致，避免混用。
- 与系统一致：若某行 `category` 留空，后端会按 **国考** 处理；**建议仍显式填写**「国考」或「省考」以便核对。

### 3. 题库 `id`（若为同一文档流程）

新题目 `id` 须 **全库唯一**（字符串，≤64）；导入相同 `id` 会 **upsert 覆盖** 原题。

- **原则**：转换前在管理后台题库列表查看 **已有 id 命名习惯**，约定本批 **第一个新题 `id`** 及递增规则（如 `lx056` 起、`ai_001` 起等）。  
- **话术**：「请确认：本次批量导入的题目，`id` 从哪一条开始、按什么规则递增？」

### 4. 若由 AI 转换：交 Word / 表格 / 说明文档前须先完成（题库）

在把 **Word**、**Excel 初稿**、**本说明 .md** 交给 **AI** 做「题库 → CSV」前，**须在提示词中明文写出**（至少）：

1. **题目 `id` 规则**：起始 id = ______，后续如何递增或命名。  
2. **若整批 `category` / `subject` 已按表统一**：可在提示词中写清；**`category` 仍须逐题判定**为 `lx`/`sl`/`yc`/`cz`/`cg`/`sl2` 之一；**`subject` 须与每行 `category` 按第二节对照表一致**。**`difficulty` 推荐由 AI 在转化时逐题识别**（见第二节「`difficulty`」说明）；若整批难度一致也可在提示词中写死同一档位。
3. **表头行**：必须使用 **第二节「题库 CSV 列定义」** 中的 **英文列名**（大小写一致），不得自创列名。  
4. **题型类**：须明确要求对 **每一道题** 判断 `category`，且 **只能** 使用第二节对照表中的 **六种代码之一**；**`subject` 须与 `category` 按第二节「标准学科名」表一致**。

> 未完成 **id 规则** 即交给 AI，易导致 **与库内 id 冲突** 或 **批量覆盖旧题**；未约定 **六码 `category`** 易导致与小程序题库模块不一致；**`difficulty` 未要求 AI 按中文三档输出** 时易出现英文档位或与业务不符。

## ★ 岗位：原始表格列 → CSV 列对照（业务约定）

| CSV 列名 | 必填 | 对应原始表格 / 说明 |
|----------|------|---------------------|
| `id` | **是** | 见上文「ID 从多少开始」，整数，自起始值递增。 |
| `name` | **是** | 对应表格中的 **「部门名称」** 列（导入后作为岗位名称展示）。 |
| `category` | **本批须统一** | **国考** 或 **省考**；每次转换前询问，本批全部相同。 |
| `subCategory` | 否 | 对应表格中的 **「招考职位」** 列。 |
| `description` | **须含全量余列** | 除已映射列外，**原始表其余全部字段**须写入本列；**书写规则见下节「`description` 补充」**。 |
| `isThreeFree` | 否 | 见下节 **「isThreeFree 填法约定」**。 |
| `payload` | 否 | 可选扩展 JSON；一般可空。 |

### 岗位 `description` 补充（表格 → CSV）

- **完整性（必守）**：`description` 中须包含原始表格里 **除已用于其他 CSV 列之外的全部剩余字段**（即：凡未写入 `id` / `name` / `category` / `subCategory` / `isThreeFree` / `payload` 的列，其信息 **一律** 合并进 `description`），**不得无故漏列、丢字段**；仅经业务书面确认可排除的列（如纯流程备注、与岗位无关的表格外信息）除外。
- **范围（与上条一致）**：已用于 `name` 的「部门名称」、已用于 `subCategory` 的「招考职位」、已用于判定 `isThreeFree` 的学历/专业/学位说明 **不再重复** 堆进 `description`，但表格中 **其余所有招考相关列** 均须出现在 `description` 中。
- **格式**：由表格转化为 CSV 文档时，写入 **`description`** 的 **每一个信息元素须单独成行**（在 Excel 中可在单元格内用 **Alt+Enter** 换行），便于转换与核对；**勿**把所有内容挤在同一行里。
- **导出 CSV**：`description` 仍只占 **一个 CSV 字段**；含换行时，该字段须用英文双引号 **整段包裹**，字段内换行与双引号按 CSV 规范转义（另存为「CSV UTF-8」时一般由表格软件处理）。

## 「isThreeFree」填法约定（与「是否三不限」一致）

字段 **`isThreeFree`** 表示 **是否三不限岗位**（与后台、代码含义一致）。

**本团队约定（与表格转换配套）：**

- 岗位对 **学历、专业、学位** 中任一类有 **明确招考限制**（非「不限」）→ **`isThreeFree` 填 `false` / `0` 等（假）**。
- **无上述限制**（典型「三不限」或表里标明不限专业/学历/学位）→ **`isThreeFree` 填 `true` / `1` / `是` 等（真）**。

**系统识别为「真」的字符串**（不区分大小写）：`1`、`true`、`yes`、`y`、`是`；其余为假。

## 一、岗位 CSV 列定义（与系统字段一致）

| 列名 | 必填 | 说明 |
|------|------|------|
| `id` | **是** | 整数主键；起始值见「转换前必做」。 |
| `name` | **是** | 业务上对应表格 **部门名称**。 |
| `category` | 建议每行都填 | **国考** 或 **省考**；空则系统默认 **国考**。 |
| `subCategory` | 否 | 业务上对应 **招考职位**。 |
| `description` | **须含全量余列** | 除已映射列外 **全部剩余字段** 写入本列；**每元素单独成行**，见 **「岗位 `description` 补充」**。 |
| `isThreeFree` | 否 | 按上文 **「isThreeFree 填法约定」**。 |
| `payload` | 否 | 一格内合法 JSON；可空。 |

**编码**：UTF-8（带 BOM 亦可）。**表头**：第一行必须为上述英文列名。

## 二、题库 CSV 列定义（与系统一致）

后端按 **表头英文列名** 读取（`csv.DictReader`），**区分大小写**，缺任一必填列或非空校验失败即该行报错。

**必填列（表头须完全一致，且单元格非空）：**

- `id`  
- `category`  
- `subject`  
- `difficulty`  
- `question`  
- `optionA`  
- `optionB`  
- `answer`  
- `explanation`  

**可选列（表头有则读；单元格有内容才作为选项）：**

- `optionC`  
- `optionD`  
- `optionE`  
- `optionF`  

**题库 `difficulty`（转化时建议由 AI 识别）**

- **做法**：由 **Word / 非结构化表格 → CSV** 时，**优先由 AI 结合题干、选项干扰度、推理量、术语难度等**，为 **每一道题** 给出 **`difficulty` 档位**；导入前由人工 **抽样复核** 可修改明显偏差。  
- **输出格式**：须为 **非空字符串**，长度 **≤16 字符**（与数据库字段一致）；**推荐三档**：**`简单`**、**`中等`**、**`困难`**，与现有小程序题库习惯一致。  
- **若 AI 输出英文**（如 `easy` / `medium` / `hard`）：写入最终 CSV 前须 **统一换算为中文三档**（或与团队书面约定的其它中文档位），**勿**中英文混用同一列。  
- **无 AI 时**：由教研按同一标准人工判定，仍须非空且满足长度限制。

**选项与答案规则：**

- 至少 **2** 个、至多 **6** 个选项；**`optionA`、`optionB` 必须非空**，否则无法满足「至少两项」。  
- **`answer`** 必须是已生成选项中的 **键**，即单个大写字母 **`A`**～**`F`** 之一，且对应列实际有内容（例如选了 `C` 则 `optionC` 非空）。  

**题库 `category`（Word / 表格 → CSV 时须逐题判定，六选一）**

字段 **`category`** 在本项目中与小程序、本地题库 **短码一致**，**每道题** 在转成 CSV 前必须判断属于下列 **哪一种**，并在该行的 **`category` 列** 填入 **下表左列代码之一**（**不得**自创其它代码，除非业务已扩展并同步后台与小程序）。

| 代码 `category` | 标准 `subject`（须与类别一致；**推荐整列与下表完全一致**） |
|-------------------|----------------------------------------------------------|
| `lx` | 逻辑推理 |
| `sl` | 数量关系 |
| `yc` | 言语理解 |
| `cz` | 资料分析 |
| `cg` | 常识判断 |
| `sl2` | 申论专练 |

- **一致性（必守）**：**`subject` 必须与 `category` 同属一大类**，**禁止**跨类混填（例如 **`category=lx` 时 `subject` 不得为「言语理解」** 等）。  
- **推荐写法**：每行 **`subject` 直接填写上表右列「标准学科名」**（与小程序首页题库模块名称一致），便于检索与质检。  
- **若须写子模块**（如 `lx` 下写「图形推理」）：仅允许 **明确属于该 `category` 大类** 的名称，且须在 **团队备案词表** 中列出；**不得**用子模块名把题划到错误大类。  
- **判定责任**：人工或 AI 转换时，**先定 `category` 六码，再按上表填 `subject`**；存疑时与管理员 / 教研对齐。

> 说明：刷题页筛选项里 `cg` 展示为「常识」、与上表「常识判断」为同一类，**导入 CSV 时 `subject` 请以「常识判断」为准**（或与备案统一为「常识」二选一，**全库统一**即可）。

**编码**：UTF-8（带 BOM 亦可）。**第一行**：上表所列表头；**第二行起**：每行一题。

## 三、Excel / WPS 表格 → CSV

### 岗位

1. 第一行表头：`id,name,category,subCategory,description,isThreeFree,payload`。
2. 按 **「原始表格列 → CSV 列对照」** 映射列；**确认起始 `id`、本批国考/省考** 后再填数。
3. **`description`**：须含 **除已用字段外的全部剩余列**；合并时 **每个元素单独成行**（见 **「岗位 `description` 补充」**）。
4. 另存为 **CSV UTF-8（逗号分隔）**。

### 题库

1. 第一行表头：与 **第二节「题库 CSV 列定义」** 中列名 **完全一致**（含 `optionA`…`optionF` 按需）。  
2. 自第二行起 **一行一题**；**`id` 按已确认规则填写**，勿与后台已有 id 无意重复。  
3. **`category` 与 `subject`**：每题 **`category` 六码判定** 后，**`subject` 须与之类别一致**（见第二节对照表；**推荐** `subject` 取表中标准学科名）。  
4. **`difficulty`**：**推荐由 AI 结合题干逐题判定**（`简单`/`中等`/`困难`）；无 AI 时由人工按同一标准填写。  
5. **`question`、`explanation`（及选项文字）** 内若含逗号、换行、双引号，整格用英文双引号包裹并正确转义（见 **第四节 §2 步骤 3**）。  
6. 另存为 **CSV UTF-8（逗号分隔）**。

> 两列表均支持直接上传 **`.xlsx` / `.xlsm`**，列名与 CSV 相同。

## 四、Word → CSV（流程与题库专项规范）

### 1. 共通说明（岗位 + 题库）

- 管理后台 / 后端 **不直接解析** Word 的 `.doc` / `.docx`。  
- 须先在 **Excel 或 WPS** 中排成 **一行表头 + 多行数据**，再 **另存为 CSV UTF-8**。  
- 另存前务必完成各表对应的 **「转换前必做」**（岗位：起始 id、国考/省考等；题库：**起始题目 id** 等）。

### 2. 题库：从 Word 到可导入 CSV（推荐顺序）

**步骤 1 — 在 Word 里整理结构**

- 若已是 **表格**：尽量调整为 **每行一题**，列顺序尽量与第二节表头一致，便于复制。  
- 若为 **「题干 + A/B/C/D + 答案 + 解析」** 的连续文字：先在纸上或 Word 里标出每道题的边界，再逐题填入 Excel，避免串题。

**步骤 2 — 粘贴到 Excel / WPS**

- 新建工作表，**第一行** 粘贴或录入 **第二节所列英文表头**（每个列名单独占一格）。  
- **第二行起** 每行一题；**不得** 省略必填列。  
- `id`：按 **「转换前必做 §3、§4」** 与管理员确认的字符串规则填写。  
- **`category`（须先做）**：**每道题** 在写入本行前，须判定其属于 **`lx` / `sl` / `yc` / `cz` / `cg` / `sl2` 哪一种**（含义见第二节对照表），**仅填入对应代码**；不得留空、不得使用表外自创代码。  
- **`subject`（须与类别一致）**：在 `category` 确定后，**`subject` 须与之类别一致**（推荐直接填第二节表中与该行 `category` 对应的**标准学科名**）。

**步骤 3 — 字段内容规范**

- **`question`、`explanation`、`optionA`～`optionF`**：可为长文本；若含 **英文逗号 `,`**、**换行**、**双引号 `"`**，在 Excel 中编辑后由软件在导出 CSV 时用 **双引号包裹整格**，内部 `"` 写成 `""`。  
- **`answer`**：只填 **一个大写字母**（`A`～`F`），且必须与存在的选项键一致（通常对应 `optionA` 的键为 `A`）。  
- **`category` / `subject` / `difficulty`**：  
  - **`category`**：**每题必判**，且只能为 **`lx`、`sl`、`yc`、`cz`、`cg`、`sl2` 之一**（含义见第二节对照表）；不得留空、不得使用未约定代码。  
  - **`subject`**：**须与 `category` 同类**（见第二节「标准学科名」）；**推荐**与表中右列 **逐字一致**；禁止 `category` 与 `subject` 跨类矛盾。  
  - **`difficulty`**：**推荐在转化时由 AI 逐题识别**（见第二节「`difficulty`」说明）；须非空、≤16 字；推荐 **`简单` / `中等` / `困难`**；人工可抽检修正。

**步骤 4 — 导出**

- 使用 **另存为 → CSV UTF-8（逗号分隔）**（名称因软件版本略有差异）。  
- 导出后用文本编辑器抽查：**首行表头无乱码**、**随机抽一行** 中英文字段与 Excel 中一致。

### 3. 题库：交给 AI 时的最少说明模板（可复制）

```text
请根据附件 Word/表格生成题库导入用 CSV（UTF-8）：
1. 表头严格为：id,category,subject,difficulty,question,optionA,optionB,optionC,optionD,answer,explanation（无 C～F 可省略列或留空单元格）。
2. 本批题目 id 从「______」起按规则「______」递增。
3. 每行一题；answer 仅为 A-F 中单字母；optionA、optionB 不得为空。
4. 每道题的 category 必须为且仅为以下之一：lx（逻辑推理）、sl（数量关系）、yc（言语理解）、cz（资料分析）、cg（常识判断）、sl2（申论专练）；须根据题干逐题判定。
5. 每道题的 subject 须与 category 一致：lx→逻辑推理、sl→数量关系、yc→言语理解、cz→资料分析、cg→常识判断、sl2→申论专练（推荐与左侧标准名逐字一致；子模块须备案且不得跨类）。
6. 每道题的 difficulty 须由 AI 根据题干与选项难度逐题判定，输出为中文：简单、中等、困难（勿用 easy/medium/hard 入库；若 AI 输出英文须先换算）。
7. 题干/解析中含逗号或换行时请按 RFC4180 风格用双引号包裹字段输出。
```

### 4. 岗位：Word → CSV（摘要）

- 列映射、`description` 全量与分行、`isThreeFree`、国考/省考、起始 id 等见 **前文「岗位」各节**；Word 同样须先落 Excel 再导出。

## 五、示例（`id`、`category` 请按当日约定替换）

**岗位（假设新 id 从 56 起、本批全部为省考）：**

```csv
id,name,category,subCategory,description,isThreeFree,payload
56,某部机关,省考,一级主任科员及以下,"招考人数:2
学历:本科及以上
专业:法学",false,
57,某局综合岗,省考,综合管理,"三不限

```

上例：`description` 内 **多条信息各占一行**（在真实 CSV 中仍属同一字段，由引号包住）；第 1 行有专业/学历等 **限制** → `false`；第 2 行为 **三不限** → `true`。

**题库（示例）：**

```csv

```

上例：`category=lx`（逻辑推理）与 `subject=逻辑推理` 一致，符合 **六码** 约定。

## 六、常见错误

| 现象 | 原因与处理 |
|------|------------|
| 岗位 id 与已有重复 | 未按「最大 id+1」；导入会 **覆盖**。 |
| 国考/省考混填未沟通 | 本批应统一 `category`，转换前书面确认。 |
| `name` 为空 | 部门名称列未映射或漏行。 |
| `description` 缺列 | 未把「除已用字段外的全部余列」写入；对照原表逐项补进 `description`，每元素单独成行。 |
| 题库 id 重复 | 与已有 id 相同会 **覆盖** 原题。 |
| 题库表头拼写错误 | 列名须与第二节 **完全一致**（如 `optionA` 勿写成 `option_a`）。 |
| `answer` 与选项不符 | `answer` 须为已填选项键之一；勿填「选项A」等全文。 |
| `difficulty` 空或超长 | 须非空且 ≤16 字；AI 识别后须人工抽检。 |
| `subject` 与 `category` 不一致 | 按第二节对照表改正；禁止如 `lx` +「言语理解」等跨类组合。 |
